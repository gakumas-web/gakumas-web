# 模拟引擎候选池兼容性审计

内容更新、映射生成或引擎升级后，先统一审计技能卡、每项附魔的全部等级和比赛 P 道具，再交付候选站点。流程仅读取公开内容，不需要账号快照、游戏凭据或网络服务。

## 日常与发布流程

1. 按现有内容安装／构建入口生成候选站点，保留内容频道与分包清单。需要修复映射时，使用 `tools/build_contest_engine.py` 的固定来源校验和映射生成入口，不能跳过定义指纹。
2. 对实际交付目录执行审计：

   ```sh
   npm run audit:engine -- --site dist --baseline tools/contest-engine-compatibility-baseline.json --report local/contest-engine-audit.json
   ```

3. 检查报告中的 `newUnsupported` 和 `resolved`。新增不支持项或同一不支持项的公开定义变化会返回非零退出码；内容哈希错误、程序缺失或审计失败同样阻止发布。
4. 修复可证明等价的映射后重新审计。确实未实现的效果继续排除，并在人工核对支持范围后显式更新基准：

   ```sh
   npm run audit:engine -- --site dist --report local/contest-engine-audit.json --write-baseline tools/contest-engine-compatibility-baseline.json
   ```

基准表示已记录的限制，不表示这些条目已支持。不要为通过发布检查而无条件覆盖基准。GitHub Pages 工作流对新构建与复用制品都执行上述检查，并保存 `contest-engine-audit` 报告制品。

排查本地源码时可增加 `--program .`，复用站点中的公开资源但校验当前源码；正式发布不使用这个参数。要求零不支持项时增加 `--strict`，任何不支持项都会返回非零退出码。报告包含内容版本、分包哈希、引擎引用提交、程序与映射哈希，以及逐项 ID、名称、原因和定义指纹，可用于定位与比较。

## 浏览器运行时

自定义推荐打开时对当前账号、舞台对应的候选池执行同一套正式 Worker 校验，完成前禁止开始搜索。不支持的技能版本、附魔项目与 P 道具不再作为可选候选，支持／排除计数和清单仅供内部检查，不显示在配置界面。

已经固定的不支持配置保留在表单中并明确提示，不静默替换或丢弃。搜索提交后再次校验固定技能、附魔、P 道具和公共卡组，失败发生在评分前；自动候选继续按支持结果过滤。审计只证明定义和映射的支持情况，不代替回忆评级、持有解锁、容量和附魔组合合法性校验，也不保证推荐分数最优。

引擎署名直接读取生成映射的来源提交，并链接到对应提交，不另行维护可能漂移的版本文字。

## 名称匹配边界

映射先采用原名称；找不到时，统一全角／半角、空白、标点和常用装饰符号。强化版本可忽略末尾展示加号，但仍按独立强化字段、计划类型和来源区分，并检查卡片结构或道具类别。归一化后存在多个候选时拒绝匹配；汉字、假名、数字和长音保留，不使用模糊相似度替代身份。能够解释的效果发生冲突时仍拒绝；映射后的公开定义继续接受完整指纹校验。

使用条件与效果触发条件的附魔分别匹配，触发原文参加指纹。姿态阶段附魔同时检查原效果、目标效果和卡片已有姿态动作，避免引擎的整卡成长机制误改另一种姿态。自动规则无法证明对应关系的条目保持排除，人工核对的上游身份映射按下一节处理。

## 固定上游身份对应

模拟行为以 `tools/contest-engine-source.json` 锁定的上游版本为准，不在本项目修正上游数值、动作或附魔补丁。名称存在汉字／假名差异、上游错字或复杂附魔尚无自动翻译时，可在 `tools/contest-engine-reviewed-mappings.json` 登记经人工核对的对应身份。每项包含公开定义指纹、上游定义指纹和核对说明；这证明身份已确认，不承诺两边效果完全等价。已知数值或实现差异也在该文件说明，并原样沿用上游。

生成器检查固定版本、双向指纹、卡片结构、道具强化状态及计划，以及附魔适用卡片和等级。任一已登记定义发生变化时构建失败，必须重新核对；不得只为通过检查刷新指纹。生成映射的来源元数据记录身份清单哈希，审计仍检查实际站点的映射和引擎文件。`--mapping-only` 仅生成映射，不重建或修改引擎包。
