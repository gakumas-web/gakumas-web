# 算法与验收的版本边界

算法方法可以复用，研究结果绑定当时的输入、引擎、预算与样本。当前本机默认基准为 `baselines/r00-r08-20261013/profile.json`，不表示生产版本仍使用当时所有参数。

## 基准合同

配置为 `format: 1`、适配器为 `contest-worker-v1`。运行时和公开内容清单由 SHA-256 绑定，每个案例另有输入与期望结果哈希；`profiles` 声明案例和搜索种子，配置同时声明预算、并发和结果语义。移动路径后需要更新配置身份及引用它的回执，不能悄悄替换参考结果。

| 身份 | 覆盖内容 | 意义 |
| --- | --- | --- |
| `evaluationId` | 非搜索模块、公开内容、适配器、抽样、候选键和评分合同 | 判断评分环境是否允许直接比较 |
| `algorithmId` | 配置明确列出的搜索模块 | 区分同一评分环境内的算法实现 |
| `inputSha256` | 正式投影输入 | 阻止不同候选映射、约束、属性和舞台误混 |
| 文件 SHA-256 | 单个搜索结果或独立评分文件 | 检测字节变化，绑定原冠军及样本 |

当前模块分组采用保守的字节身份。一些不影响评分的依赖改动也可能改变 `evaluationId`，工具不推断语义等价。将评分职责移入搜索模块时必须重新审查分组，不能借分类绕过评分一致性检查。

## 回归和比较

- `exact` 要求同评分环境，检查候选顺序、逐局分数及局数。搜索算法改动引起不一致，不自动等同于质量下降。
- `observe` 记录新源码在所选固定输入上的结果，不使用旧分数判定质量，返回 `passed: null`。它不自动适配新的模块清单、内容或 API。
- `compare` 使用 `format: 2` 协议和 `evidence` 回执；逐项绑定基线、候选、独立评分的案例、角色、输入与版本。一个协议中的评分环境、基线算法身份与候选算法身份必须分别一致。
- 原冠军在独立评分前锁定，不按外评结果重新挑选。搜索、局部改进、复筛和最终复评均计入成本；耗时只作当前设备上的粗筛。
- R01 示例的 `historical-binding` 表示按已有记录补建身份，不能冒充实验当时生成的证明。提取时只重定向文件位置，保留原模块身份及原始结果。

## 引擎或数据升级

1. 新增基准配置，明确模块、内容、输入和适配合同的变化；不覆盖旧参考答案来消除失败。
2. 用正式支持范围审计确认新引擎，再通过正式构建器生成新输入。
3. 在新评分环境建立现行算法的基线；旧候选只有重新映射、校验并评分后才可能复用。
4. 新旧算法使用同一新评分环境比较，提前固定质量门槛和完整预算，另留未参与开发选择的配置与种子。
5. 根据实际证据决定是否采用；工具不自动调整生产参数或发起发布。

基准材料缺失时需重新准备符合合同的资料。已清理的历史实验树和压缩包不再是恢复入口；本工具只承诺其明确保留的命令和输入合同。
